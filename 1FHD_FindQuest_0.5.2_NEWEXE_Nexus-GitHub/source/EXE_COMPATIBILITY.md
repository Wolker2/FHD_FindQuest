## Совместный сброс

В исходном FindQuest очистка стояла под ключом 01. QuestMarker 0.3.12 использует
этот же ключ для FHD_RouteClear. В FindQuest ключ перенесён на 03; все поля и
строки 00–02 QuestMarker сохраняются в обоих порядках объединения.
verify_pair.py использует контрольную основу из конфигурации QuestMarker с
удалённым обработчиком и добавленным именем ButDel; это не полный ванильный
Main.dat. Адаптер JavaScript проверяет обе метки, сброс маршрута и повторное
нажатие. Сам RScript VM этим тестом не исполняется.

## Проверки

Из папки мода:

```sh
bash SOURCE/Native/build.sh
python3 -B SOURCE/verify_release.py /path/to/Rangers.exe
python3 -B SOURCE/verify_native.py /path/to/Rangers.exe
python3 -B SOURCE/verify_script_identifiers.py /path/to/Rangers.exe
python3 -B SOURCE/verify_pair.py /path/to/Rangers.exe /path/to/FHD_QuestMarker_Preview
python3 -B SOURCE/verify_ui.py
python3 -B SOURCE/verify_isolation.py
python3 -B SOURCE/verify_offers.py
python3 -B SOURCE/verify_layout.py
```

Нативные проверки требуют unicorn 2.1.4; совместная загрузка — pefile 2024.8.26.
Скриптовые проверки используют Node.js. DLL повторно собирается побайтово.
Игру под Windows здесь не запускали. Полное построение реальных заданий после
начальных проверок допуска, настоящий выборщик боёв и Windows RtlUnwind
в этих тестах заменены управляемыми вызовами; их игровое поведение полностью
не воспроизводится.
